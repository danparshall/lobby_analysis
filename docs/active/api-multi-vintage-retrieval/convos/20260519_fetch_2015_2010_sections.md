## Summary

This session executed two stacked operations that together populated the bulk of the 2010 + 2015 statute substrate for the 13-state set from the 2015 handoff.

**First operation: execute the 2026-05-18 handoff `20260518_fetch_2015_section_bodies.md`.** Ran the Cloudflare probe (TX 2015 single-section pull returned 145 KB of real statute HTML with no challenge), then drove the section fetch for 13 states sequentially. Started at the handoff's specified 5s `rate_limit_seconds`; the user requested mid-run to halve it to 2.5s, which we cut over between WI and WA (clean state boundary). All 13 states landed at 271 total files, zero CF re-engagement.

**Second operation: extend to 2010 vintage for the same 13 states.** The 2010 case differed structurally from 2015: there were no pre-built canary bundles for the 10 missing states (3 of the 13 — WI/OH/CA — were already populated from the archived `statute-retrieval` branch). So the work split into two passes: (a) URL-discovery via four batches of 3 parallel Claude Code subagents each (mirroring the 2015 subagent-dispatch pattern from the 2026-05-18 work) producing `<STATE>_2010/result.json` canary bundles; (b) section fetch driven by a clone of the 2015 driver script, consuming the 137 URLs the subagents produced. Three states needed `actual_vintage_used` substitution (TX→2009, CO→2016, WA→2009); the CO 2016 substitution is outside the ±5 window the pass-1 prompt suggests, but is the only available Justia vintage.

**Third deliverable: a 2025 handoff doc** for Dans-MacBook-Air to pick up the 2025 URL-discovery + section-fetch work in parallel. Deferred procedural detail to the 2015 handoff and only documented 2025-specific deltas (vintage substitution risk, no canary bundles exist yet for any state except the curated OH/2025).

## Provisional Findings

- **Cloudflare on Dans-MacBook-Pro held cleanly through ~450 Justia hits this session** (271 at 2015 + ~40 at 2010 URL discovery + 137 at 2010 section fetch). Zero re-engagement. This is a meaningful update against the 2026-05-18 escalation pattern (afternoon CF blocks at pass-3 then pass-1); either an IP-state aging effect or a different time-of-day signal.
- **The 2.5s rate limit is safe** — 271 + 137 = 408 sequential fetches without trigger. The 2026-05-18 handoff was conservative at 5s; 2.5s appears equivalently safe from this IP.
- **`statute_retrieval.retrieve_statute_bundle()` is idempotent + atomic enough for kill-resume**, but the partial-bundle gotcha is real: if the script is killed mid-state, the partial-section dir exists and the next run's `if dest.exists(): skip` guard treats it as done. Remediation in this session: manually `rm -rf` the partial WA/2015 dir between kill and restart.
- **IL has dramatically different page granularity across vintages.** IL 2010 = 3 URLs (inline single-page acts); IL 2015 = 12 URLs (per-article TOCs). Same statutory coverage. Section bodies are larger but fewer files at 2010.
- **WA at 2010 has a structural coverage gap.** Justia's 2009 listing (the substituted vintage, since 2010 is hosted only as a 7.7 MB monolithic volume page with no per-section URLs) starts at 42.17.030 — missing the 2010 analogues of 42.17A.005 (definitions) and 42.17A.020 (reports-as-public-records). The agent surfaced this as a `notes` line rather than papering over.
- **CO 2010 is structurally unavailable on Justia.** Justia hosts no CO before 2016. The 2016 substitution is outside the ±5 window the pass-1 prompt suggests; the bundle is preserved as the only-available record. Content is byte-identical to `data/statutes/CO/2015/` (which was also 2016-substituted).
- **TX 2010 also unavailable.** Substituted to 2009 — matches the curated path `("TX", 2009)` in `src/scoring/lobbying_statute_urls.py`. Within ±5.
