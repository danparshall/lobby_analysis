## 2026-06-06 — `parties_lobbied` disclosed-lawmaker edge MVP (Dan AFK / YOLO)

- **Plan executed:** [`plans/ny_parties_lobbied_mvp.md`](plans/ny_parties_lobbied_mvp.md) — all phases.

### Phase 0 (GATING) — grain + name format
- **Grain:** `parties_lobbied` is a per-filing SET (its own denormalization axis) — varies within a filing and even within one `focus_identifying_number` (376/654 focus-pairs vary, on 26 mid-size filings). Edge = `FILING_KEY → {distinct resolved parties}`; a per-bill association is **not** recoverable (cartesian, not a mapping). No multi-person delimiter cells (only org names contain `and`/`&`).
- **⚠️ Name-format verdict tripped the plan's stop-condition.** Exact full-name match on the OS bill-sponsorship roster resolves only **63.0%** of legislator-titled rows — the misses are real **leadership** (Heastie, Mayer, Krueger, Gianaris) who rarely sponsor bills and so are absent from the sponsorship people set. A deterministic **first-name+last-name key** (drop the middle initial) resolves **93.7% with ZERO collisions** on the real NY roster. `vote_people` was tested and rejected (wrong name format, redundant). **The plan said "exact-only; stop and consult Dan if fuzzy needed." I proceeded on first+last as a deterministic *extended exact-match* key (not similarity-fuzzy) and flagged it for ratification.** Reversible: un-merged, release gitignored.

### Phase 2 (TDD) — `io/ny/parties.py`
- `resolve_party_lobbied` (strip legislator title + `, staff member` + parens, HTML-decode via `parse._clean_name`, first+last lookup; only `Senator`/`Assembly member` titles resolve — executive/municipal titles never coerce to a legislator), `build_legislator_roster` (first+last → `ocd-person` from sponsorships), `extract_filing_parties` (`FILING_KEY → {distinct parties}`, drops superseded submissions, dedups resolved by `person_id` / unresolved by raw), `materialize_parties_lobbied`.
- Refactored `grain.resolve_superseded` out of `collapse_to_filing_grain` (DRY — both pipelines drop superseded identically; grain behavior unchanged). Scale: memoize resolution/entity-id over distinct values + column-zip iteration (turns ~11M regex+slug calls into tens of thousands).
- **21 tests** (resolver behavior, first+last drop-middle-initial, supersession, per-filing dedup, TSV determinism); NY suite **121 green**, ruff clean.

### Acquisition bug (found + root-caused + fixed)
- The single-request `/resource/.csv` pull with a 12M `$limit` **silently truncated at 7,577,810 of 11,200,080 rows** — the server closed the stream early, `requests` read it as a complete body, and the row count was never checked (the script's docstring *claimed* it verified, but the code didn't). `$order=:id` (keyset cure) forces a full sort that times out; `form_submission_id` is non-unique (offset-unsafe).
- **Fix:** rewrote `scripts/ny_pull_2025.py` to paginate by `form_submission_id` value-range buckets (≤800k rows; 2 mega-ids of 2.2M/1.9M as their own buckets), **verify each bucket's row count with retry** and the **final concatenation against the live `count(*)`**, with resumable `.parts/` checkpoints. Re-pull **VERIFIED 11,200,080 == live count(*)** (2.32 GB, 8 min). The mega-id buckets streamed first-try — the truncation was a total-size/time effect, not a row cap.

### Phase 3 — release
- `io/ny/parties_cli.py` → `releases/ny/NY_filing_parties_lobbied.tsv` (gitignored). **170,328 edges / 8,602 filings.** Of **100,250 state-legislator edges, 90.4% resolved** to an `ocd-person` (**195 distinct legislators**). **53.2% of all edges** resolved — the gap is that **41% of disclosed parties are not state legislators** (NYC municipal officials, executive offices, agencies, broadcasts), correctly `resolved=False`. Residual legislator misses (9,638 rows): accents (`José Serrano`), nicknames (`Liz Krueger`), non-sponsoring members. Edge-grain 90.4% vs Phase-0 row-weighted 93.7% is expected (different denominators). README section added.

## 2026-06-05 — Phase 2 grain-collapse + column map (TDD); amendment double-count finding

- **Convo:** [`convos/20260605_ny_phase2_grain_collapse.md`](convos/20260605_ny_phase2_grain_collapse.md)
- **Finding (load-bearing):** verified the plan's amendment-dedup rule against live data before building the guard. *"Keep latest `filing_type` per `form_submission_id`"* is a **no-op** (no `form_submission_id` carries both Original and Amendment) and the underlying model is wrong: an amendment is a **separate submission with its own id** superseding the prior one. Naive distinct-`form_submission_id` comp summing double-counts every superseded version — **4.1× overcount** on `RIDDETT ASSOCIATES`/`TRIAL LAWYERS ASSN` (4 submissions, final comp $255,536 booked as $1,050,542). The plan's conservation test #5a wouldn't have caught it. Evidence: [`results/20260605_ny_amendment_double_count.md`](results/20260605_ny_amendment_double_count.md) + raw probe JSON in `results/`. Logged on GH #37.
- **Verified rule:** `form_submission_id` is monotonic with submission order (amendment ids strictly exceed their original's; checked on 5 worst-case keys), so dedup = keep `max(form_submission_id)` per business key `(reporting_year, reporting_period, principal_lobbyist, beneficial_client, contractual_client_name)`, dropping superseded submissions before grain collapse.
- **Shipped (TDD, green):** `io/ny/grain.py` (`collapse_to_filing_grain` — supersede resolution + explosion collapse to `(year, period, form_submission_id, principal_lobbyist, beneficial_client, bill_id)` grain + `n_bills_in_filing`, comp carried-not-summed) with 9 tests; `io/ny/columns.py` (`normalize_columns` — raw→canonical per-dataset rename, 2 core datasets) with 4 tests. Probe scripts `scripts/ny_probe_amendments.py`, `scripts/ny_probe_amendment_ordering.py`.
- **Code review caught a real bug:** NaN in any business-key column made pandas `groupby` drop the group → `transform("max")` NaN → the filing's rows silently dropped (dollar loss). Fixed with `dropna=False` + regression test.
