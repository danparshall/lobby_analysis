# Backend v0 End-to-End Demo

**Date:** 2026-05-28
**Branch:** `backend-prototype`
**Status:** v0 working — fixture filing ingested via CLI, served via FastAPI, hand-verified against the source.

## What was demonstrated

The v0 backend goes round-trip from a `LobbyingFiling` JSON file → SQLite storage → HTTP responses, with no missing pieces in the prototype slice.

## Setup

1. Built a hand-crafted fixture `tests/fixtures/backend/oh_aichele_sample.json` shaped after the OH Aichele / ARC Gaming legislative AER (4 bills: HB 96, HB 298, HB 344, SB 197; $20.00 Section II.D aggregate expenditure). Hand-built rather than LLM-extracted to keep the demo independent of the workspace API quota / VPN constraints on `oh-portal-extraction`.
2. CLI ingestion:
   ```
   PYTHONPATH=src .venv/bin/python -m lobby_analysis.backend ingest \
       tests/fixtures/backend/oh_aichele_sample.json
   # → prints "oh-1427844"; creates data/backend/prototype.db (28 KB)
   ```
3. `list` subcommand confirms persistence:
   ```
   PYTHONPATH=src .venv/bin/python -m lobby_analysis.backend list
   # → oh-1427844	OH	activity_report	lobbyist	Nathan Aichele
   ```
4. Started uvicorn:
   ```
   BACKEND_DB=data/backend/prototype.db PYTHONPATH=src \
       .venv/bin/python -m uvicorn lobby_analysis.backend.api:app \
       --port 8765
   ```

## Endpoint walkthrough

### `GET /filings`

Returns the full ingested filing as a JSON array. Verified: id, state, filing_id, filer_person, filer_organization, reporting period, filed_date all present and correct.

### `GET /filings/oh-1427844`

Returns the full nested record. Spot-checked fields from the response body:

```
id:                       oh-1427844
state:                    OH
filer_person.name:        Nathan Aichele
filer_organization.name:  ARC Gaming & Technologies
filed_date:               2025-09-03
total_expenditure:        20.0
num_positions:            4   ← HB 96, HB 298, HB 344, SB 197
num_expenditures:         1   ← Section II.D aggregate
```

All values match the source fixture.

### `GET /search?q=Aichele`

Returns 1 hit (id `oh-1427844`). Case-insensitive substring match against the denormalized `filer_name` column.

### `GET /filings/no-such`

Returns HTTP `404`. Confirms not-found path returns the right status.

## Notes for the next session

- The `PYTHONPATH=src` workaround is needed on this machine because macOS marks the editable `.pth` file as hidden and Python 3.12+ skips hidden `.pth` files. Root cause is local to this Mac (also affects `_virtualenv.pth`); not in the repo. See memory `project_macos_hidden_pth_breaks_editable_install`.
- The OH Aichele filing currently uses both `filer_person` and `filer_organization`. The `LobbyingFiling` schema docstring says only one should be set — but OH filings are made by an agent (person) on behalf of an employer (org), and the v1.x schema has no `filer_employer` field. This is the same `(agent, employer)` schema gap pre-flagged on the `oh-portal-extraction` branch. The fixture ignores the constraint for now; v1.4 conversation will resolve it.
- The fixture lives at `tests/fixtures/backend/oh_aichele_sample.json` — when Dan's LLM-extracted OH filing JSON arrives, it can replace the hand-built fixture if its shape matches.
