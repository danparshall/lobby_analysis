## Why this week mattered

**The pivot is the story.** Two weeks ago, Prong 1 was "mostly built" — 3 of 4 components shipped, the 4th had a 1400-line TDD-shaped plan, and the next deliverable was the first Ralph-loop iteration. This week's Tier-1 + Tier-2 evidence forced a different question. The empirical answer was good (LLMs read statutes reliably — high cross-vintage stability, no hallucinated citations, $2.94 / 84 cells); the load-bearing finding was that **the typed-cell schema we were going to extract *into* can't represent what the statute actually says** for qualitative-trigger states. Both models agreed at the level of statute interpretation; both produced wrong projections downstream because the cell shapes pre-suppose numeric answers.

**This is not a step backward; it's a step that couldn't have been taken from a planning artifact.** The original Compendium 2.0 design (181 cell-typed rows, frozen 2026-05-13) was the best schema we could draft from reading rubrics. The pilot showed which assumptions in that draft survive contact with statute reality. Three things survive: (1) the rubric mapping work — the 9 projection specifications are formal definitions of what each rubric scores, re-adaptable to v2.2 cells; (2) the extraction infrastructure — dispatch, chunking, parser, multi-model side-by-side, σ_noise measurement; (3) the empirical finding that LLMs *can* read statutes. The schema-first-at-extraction-time assumption is what v2.2 will revisit.

**Sycophancy-trap caught in real time.** The pivot session almost went a different way. The agent proposed a "schema discriminator cell" solution that would have engineered cross-rubric projection agreement — exactly the Goodhart trap [`docs/RESEARCH_ARC.md`](https://github.com/danparshall/lobby_analysis/blob/main/docs/RESEARCH_ARC.md) names as Risk #2 ("Prompt tweaks that minimize projection-distance can push the LLM toward cells that project well, not cells that are correct"). User caught it by asking whether the doc had been read. Worth flagging because the doc *exists for exactly this kind of trap* and the agent still walked into it; logging as a process note that pre-flight reads need to actually land in the working framing, not just get read mechanically.

**Prong 2 picks up the load.** With Prong 1 paused, the immediate product focus shifts to state-by-state disclosure data pulls. WI joined NC this week as a parallel exploration; the WI session surfaced a portal pattern (no bulk authorization export, but a clean foreign key in per-entity HTML pages) that we should expect to recur. The lobbyist-side scrape design also generalizes — pick whichever side has smaller pages and the cleaner ID structure as the foreign key root, validate symmetrically from the other side if cost permits.

## One new framing + one refinement of last week's

1. **(New) "Gather first; design schema after."** v2.1 — the current frozen 181-row TSV — remains the immediate reference for downstream work. **v2.2 — the next compendium generation — gets designed *from observed statute reality*, not from rubric reading.** Concretely: collect per-(state, vintage, question) answers in flexible intermediate JSON (freeform answer + statute citation + confidence) across priority states first, then look at what shapes the answers actually take and design the typed schema to fit. The structural assumption being revisited is "schema → extract → project"; the new assumption is "extract → observe → schema → project." This is a strategy shift, not an abandonment of typed cells as a long-term goal.

2. **(Refinement of last week's Ralph loop)** Last week's "noise floor first, then iterate" framing for Prong 1's optimizer is on ice along with Prong 1. The noise-floor measurement itself **did happen** (σ_noise Claude 85.7%, GPT 73.8% on OH 2025 legal axis, deflated by unpinned enums) and is reusable when Prong 1 resumes against v2.2 cells. The Phase C projection functions also survive — they're formal specifications of each rubric's substantive scoring rule, decoupled from v2.1 cell shapes by their `f(cells, state) → score` signature; they'll re-target v2.2 cells when the new schema lands. **What's deferred:** the Ralph loop itself (no point optimizing extraction *into* a schema we know is incomplete).
